# 智慧综合治税与税收风险智能分析平台 · 静态演示工程

面向地市级税务局的政务内网系统前端演示工程。
技术栈 **Vue 3 + Vite + Vue Router + ECharts**，**不引入任何 UI 组件库**，全部组件自绘。

视觉与布局 1:1 复刻设计稿，设计令牌以 `src/styles/tokens.css` 为唯一来源。
基调：专业、克制、可信 —— 不做互联网产品的活泼感，不做大屏炫光效果。

设计稿来源两处：Claude Design 项目（6 张业务稿 + 设计系统 / 平台侧栏 / 交互说明），
以及 `doc/` 目录下的决策分析高保真交付包（4 张 `.dc.html` + handoff 说明）。
`doc/` 仅作实现参考，不参与构建。
无设计稿的页面按批次自绘，规矩见 [§二.5](#5-无设计稿页面18-页)。

## 一、快速开始

### 1. 环境要求

| 项 | 要求 | 当前验证环境 |
|---|---|---|
| Node.js | ≥ 18（Vite 5 要求） | v22.20.0 |
| npm | ≥ 9 | 10.9.3 |
| 浏览器 | Chrome / Edge 80+ | — |

### 2. 安装依赖

```bash
npm install
```

> **内网 / 公网源不通时**，改用国内镜像（只对本次安装生效，不改动全局配置）：
>
> ```bash
> npm install --registry=https://registry.npmmirror.com
> ```
>
> 若安装中断过，先清理再装：
> `rm -rf node_modules package-lock.json`（Windows PowerShell：`Remove-Item -Recurse -Force node_modules, package-lock.json`）

### 3. 启动前端服务（开发模式）

```bash
npm run dev
```

启动后终端输出：

```
  VITE v5.4.21  ready in 277 ms

  ➜  Local:   http://localhost:5173/
```

**浏览器访问：<http://localhost:5173/>**
默认自动重定向到领导驾驶舱：`http://localhost:5173/#/dashboard`

> 采用 **hash 路由**（`#/`），因此可直接部署到任意静态服务器，无需后端配置 URL 重写。

常用参数：

```bash
npm run dev -- --port 8080     # 指定端口（默认 5173，被占用时自动顺延）
npm run dev -- --host          # 暴露到局域网，供同网段其他机器访问
npm run dev -- --open          # 启动后自动打开浏览器
```

停止服务：终端按 `Ctrl + C`。

### 4. 生产构建与本地预览

```bash
npm run build      # 类型检查(vue-tsc) + 生产构建，产物输出到 dist/
npm run preview    # 以静态服务器预览 dist/，默认 http://localhost:4173/
```

`dist/` 为纯静态文件，可直接拷贝到 Nginx / IIS 等任意静态服务器的站点目录下部署。

### 5. 常见问题

| 现象 | 处理 |
|---|---|
| 端口 5173 被占用 | Vite 会自动顺延到 5174…；或用 `--port` 指定 |
| 页面空白 | 确认访问的是带 `#/` 的地址；打开 DevTools 控制台查看报错 |
| 图表不显示 | 图表容器高度依赖父级 flex，若自定义了布局需保证容器有实际高度 |
| 接口报错 | 检查 `.env` 的 `VITE_API_MODE`，演示默认为 `mock`，无需后端 |

## 二、功能架构

### 1. 总体结构

全局为「固定侧栏 + 内容区」两栏布局，所有业务页共用侧栏：

```
┌──────────┬────────────────────────────────────────────┐
│          │  页面自带标题栏（页名 + 筛选 + 更新时间）      │
│  全局侧栏 │────────────────────────────────────────────│
│  210px   │                                            │
│  深色表面 │            业务页内容区（router-view）        │
│  折叠菜单 │                                            │
│          │                                            │
│ v1.0 页脚 │                                            │
└──────────┴────────────────────────────────────────────┘
```

- 侧栏固定 210px，深色表面色自成一套中性色，不与浅底灰阶混用
- **两级折叠菜单**：9 个一级 + 34 个二级；点击一级分组折叠/展开，默认展开当前所在分组
- 当前页高亮：反白文字 + 16% 浅蓝底纹 + 左侧 `#5FA8D3` 色条；详情页（如 `/clues/:id`）也能点亮所属菜单
- 「风险线索池」带红色待处置数量角标
- 菜单是唯一数据源 `src/config/menu.ts`，路由由它生成；`status='placeholder'` 的项统一落 `PlaceholderView`（展示"本模块建设中" + 功能说明，不像报错页）

### 4. 决策分析模块（4 页）

依据 `doc/` 下的高保真交付包（`README.md` + 4 张 `.dc.html` + 《交互说明》）**像素级复刻**。
四页共享顶栏筛选（时间 / 区县 / 导出）与全站统一悬停 Tooltip；筛选、tab、排序、分页、
节点选中均为**页面本地 state，不跳路由**。

| 页面 | 核心可视化 | 交互 |
|---|---|---|
| **收入分析** | 双进度条（时间/收入）+ 红色**序时线**标记；同比归因**瀑布**（SVG）；分级次**堆叠柱**（DOM）；全年预测折线 + **90% 置信区间**（SVG） | 表头排序（▲▼/⇅）；**点击行下钻区县子行**；图元悬停 tooltip |
| **税源分析** | **帕累托**（TOP15 柱 + 累计占比线 + 80% 参考线）；集中度 CR5/10/50 + **对数宽度**规模梯队；税源流动**双向柱**（零基线上下堆叠）；行业结构 **100% 堆叠面积**；区域**气泡矩阵**（均值虚线四象限） | 6 处图元悬停明细；区县排行联动阅读 |
| **治税成效分析** | 5 环节**闭环链条** + 96px 连接器（转化率徽章 / 流失去向）；下钻明细 3 列迷你条；数据源横条；规则引擎 vs 智能模型**分组柱** | **点击环节**切换下钻明细；对比维度 3 tab；排行表排序 + 分页 |
| **专题分析** | 房地产**六环节链条**（税种芯片 + 风险角标）；建筑安装**合规象限散点**（右下风险区底纹）；平台经济卡 + 商户分布**双柱直方图** | **专题 tab 切换替换整个内容区**；节点 / 平台卡选中；风险清单联动 |

图形实现方式：**原生 SVG / DOM 绘制**（非 ECharts）——设计稿为逐坐标定制图形，
自绘才能保证 1:1；几何计算（瀑布累计、对数宽度、气泡半径、置信区间多边形、象限阈值）
全部在组件内完成，接口只下发业务数值。

配套复用件：`composables/useTooltip.ts` + `components/charts/ChartTooltip.vue`
（fixed 定位、视口边缘钳位、下缘自动翻转），四页共用。

### 5. 无设计稿页面（18 页）

无设计稿的页面按批次实现，规矩有三条:

1. **先声明范式**：动手前先指明参照哪个已有页面 —— 列表筛选类 → 风险线索池;详情展示类 → 一户式主档;图表分析类 → 领导驾驶舱。
2. **严格复用令牌与组件**：不出现任何硬编码色值 / 字号;优先复用 `components/common`,确无对应件才新建并放入公共目录。
3. **分层纪律不变**：先在 `types.ts` 定接口 → 再写 mock 与 http → 最后写页面;页面不直连 mock。

| 批次 | 模块 | 页面 | 参照范式 / 关键实现 |
|---|---|---|---|
| 1 | 决策分析 | 收入 / 税源 / 治税成效 / 专题 | 见 §4（后转为 `doc/` 交付包 1:1 复刻） |
| 2 | 数据治理 | 接入监控 · 质量看板 · 主体识别与匹配 | 看板 + 列表;主体识别含冲突比对面板 |
| 3 | 风险管理 | 任务派发 · 结果回填 · 处置绩效统计 | 见下「风险管理的页面关系」 |
| 4 | 规则库管理 | 规则试跑与灰度 · 阈值参数管理 · 规则效果监测 | 与「规则配置」刻意区分视角:配置页是**单规则**（定义/阈值/效果三标签）,本组是**跨规则**（试跑队列 / 全库参数审计 / 全库效果横向对比） |
| 5 | 智能模型 | 风险评分模型 · 虚开团伙识别 · 异常申报检测 · 行业税负基准 | 见下「智能模型 4 页的区分」 |
| 6 | 税源监控 | 重点税源监控 · 收入预测分析 · 新办企业评估 | 见下「税源监控 3 页的区分」 |
| 7 | 智能应用 | 文书辅助生成 · 资料智能处理 · 自然语言取数 | 见下「智能应用 3 页的区分」 |

**智能模型 4 页的区分**（最容易做成同一个模子，故刻意分化）:

| 页面 | 单位 | 版式 | 主可视化 | 方法 | 归因形态 |
|---|---|---|---|---|---|
| 风险评分模型 | 户 | 模型态 + 结果态,右抽屉 | Lift 曲线 + 特征重要性 TOP20 | 有监督 XGBoost | **SHAP 双向发散条**（推高/压低分色,给出取值与同业中位） |
| 虚开团伙识别 | 团伙 | 表在上、下钻在下 | 团伙子图（环状/星状/链状三种布局算法） | 图结构 + 开票行为 | **认定依据证据清单**（命中/未命中都列,权重归一到可疑度） |
| 异常申报检测 | 户（同业对比） | 图上表下、图表联动 | **平行坐标**:同业样本铺底成分布带,选中企业高亮出带 | **无监督离群**,不用历史查实标签 | **各维度同业分位 + 偏离 σ** |
| 行业税负基准 | 行业 | 图表驱动三段式 | **箱线图**（Q1/中位/Q3/1.5×IQR 须端 + 离群点）+ 企业散点分布 | 分位数统计 | **基准测算口径**:样本范围 / 5 条剔除规则 / 计算方法 / 调整记录 |

四页共同遵守两条合规要求（需求文档）:

- 页顶栏之下常驻 `ModelNotice` 免责声明条，**不随内容滚动**:「模型输出仅用于风险提示与线索排序,不作为税务定性依据。」
- 每条模型结果旁**常驻**「查看归因」入口（不是 hover 才出现）;归因面板底部另有针对该模型的加强表述（如「离群不等于违规」「认定依据不等同于虚开事实」）。

**税源监控 3 页的区分**（形态刻意不套同一骨架）:

| 页面 | 骨架 | 列表件 | 展开方式 | 主可视化 |
|---|---|---|---|---|
| 重点税源监控 | KPI + 预警区 + **分档标签页(A/B/C)** + 名录表 | `DataTable`(末列内联 `Sparkline`) | **整页切详情态** | **多指标同步时间轴**:税额/开票量/社保/用电共用时间轴、量纲不归一、悬停竖线贯通 |
| 收入预测分析 | **主图占首屏** + 摘要卡 + 误差回溯 + 明细表 | `DataTable` | 无 | 历史段弱化、预测段粗虚线 + 90% 置信带 + 未来区底纹;**误差回溯**柱正负分色 + ±5% 可接受带 |
| 新办企业评估 | **四象限散点 + 时间流** | **自绘时间流,不用表格** | **行内手风琴** | 空壳风险 × 税源潜力四象限,气泡按面积开方映射注册资本 |

「重点税源监控」的下降归因是本模块的关键设计:税额与开票量同步回落、但社保与用电平稳,
于是「经营下滑」被这两条数据**排除**(可能性 34%),「政策性减免」以 62% 居首 —— 交叉印证的价值就在这里。

**智能应用 3 页的区分**（三页加上政策智能问答很容易全做成聊天框,故只保留一个聊天形态）:

| 页面 | 形态 | 有无输入框 | 关键约束 |
|---|---|---|---|
| 文书辅助生成 | **参数表单 + A4 文档编辑器** | 无 | 落实需求 5.3「**严禁模型生成任何数值**」:正文按 segment 区分,`data` 片段浅蓝底 + 锁标 + `contenteditable=false`(悬停查数据来源),`model` 段落带角标可自由编辑 |
| 资料智能处理 | **三栏核对工作台** | 无 | 左原件右字段**按坐标双向联动**;原件由接口下发版式块绘制,字段 `box` 与版式同坐标系;置信度低于阈值标黄并要求逐项确认 |
| 自然语言取数 | **对话流** | 有 | 回答载体是**图表/表格**而非文字;侧栏是**指标字典**而非引用来源;额外常驻**语义解析**(含未识别词)与可折叠 **SQL**(内含数据权限子查询,与底部提示互证) |

| 风险线索池 | **管理者** | 全局线索、单条与批量手工派发 |
| 任务派发 | **管理者** | **派发策略配置**:规则(管辖分局/行业专业化/人员负荷,可调启用、权重、优先级)+ 人员负荷看板 + 按策略试算 → 确认执行 |
| 核查处置工作台 | **办理人** | 无参数看**我的待办**(四状态标签 + 任务卡,超期置顶);`?taskId=` 直达办理,顶部可上一条/下一条连续办理 |
| 结果回填 | 办理人 | **只列不办**:待回填任务列表,点击跳 `?taskId=xxx&tab=result`,由工作台承载唯一一份回填表单 |

两条设计取舍:

- **回填表单只保留一处**。此前结果回填页虽复用 `DisposalForm`,但仍是第二个提交入口,状态与校验容易漂移。
- **工作台不切三栏标签**。左栏风险点与比对数据在填表时必须常驻可见,故标签页只设在右栏(结果回填 / 核查过程),时间线从左栏移入。
- **自动派发不硬派**。全员超载的线索如实列入「无法分派」清单并给出原因;规则一改,已有试算结果立即作废并要求重算。

**菜单角标与列表同源**:`menu.ts` 不提供静态角标字段,只声明 `badgeKey`;侧栏调 `clues.getCluePendingCount()`
取「待派发」线索数。写死的数字必然与列表脱节 —— 此前菜单显示 137、列表只有 24 条就是例子。

**演示数据自洽**:48 户评分样本是主线 —— 团伙成员、异常申报离群企业、基准散点的头部样本全部取自同一批，
因此四页里点到同一家企业，分值口径一致;评分样本的前 24 户又直接取自风险线索池数据集，
使「评分 → 线索 → 核查」形成一条可验证的链路，而不是各页各写一份互不相干的假数据。

### 3. 取数分层（硬约束）

页面组件**只能**通过 `src/api/client.ts` 取数，**禁止**直接引用任何 adapter。

两套 adapter 都实现 `types.ts` 中的 `ApiClient` 接口，
**函数签名由 TypeScript 编译期保证完全一致**，切换实现不需要改任何页面代码。

切换方式（`.env`）：

```bash
VITE_API_MODE=mock          # mock（默认，无需后端） | http
VITE_API_BASE_URL=/api      # http 模式下的后端基地址
```

**颜色不进契约**：后端只返回语义值（如 `accent`、`deltaTone`、`isForecast`），
具体色值由前端在 `src/charts/palette.ts` 中按设计令牌映射，
因此 `types.ts` 中不出现任何 hex 色值。

### 4. 数据区块四态

依据《交互说明》第 2 节，每个数据区域（卡片 / 图表 / 表格）**独立**四态：

```
加载中 → 有数据 / 空 / 错误
```

- 容器尺寸在四态间保持不变，避免布局跳动
- **局部失败不影响其他区块**（如图表失败但指标卡正常）
- 加载态用呼吸式骨架条（1.2s，透明度 100%↔60%），不使用旋转 spinner
- 错误文案面向业务人员，不暴露堆栈与错误码
- 由 `useResource`（含请求竞态保护）+ `StateBlock` 实现

### 5. 设计令牌

**代码中不允许出现字面量颜色、字号、间距**，一律走 CSS 自定义属性。令牌分三层：

| 层级 | 位置 | 承载内容 |
|---|---|---|
| **全局设计系统** | `src/styles/tokens.css` | 《设计系统》定义的通用值：主色四档、辅色、深色表面 6 色、9 级中性灰阶、风险三级与状态三态（含文字色与底纹色）、8 色图表序列、字号字重行高（含 11px 微型字号 `--fs-micro`）、4px 基数间距刻度、圆角/描边/阴影、动效时长 |
| **页面级** | 页面根选择器，如 `DashboardView.vue` 的 `.dash { --dash-* }` | 来自设计稿但**不在**全局字阶与 4px 刻度内的本页专有度量（如 38px 指标数值、20px 栅格间距、68px 标题栏高） |
| **组件级** | 组件根选择器，如 `DonutChart.vue` 的 `.donut { --donut-* }` | 该组件专有度量（如 190px 环形直径、11px 图例色块） |

页面级/组件级令牌**不写入 `tokens.css`** —— 那里只承载全局设计系统，避免被单页尺寸污染。
CSS 自定义属性沿 DOM 继承，页内子组件可直接引用上层令牌。

> **例外**：`src/charts/palette.ts` 中保留 hex 字面量。ECharts 的 option 与 SVG 的
> `fill`/`stroke` 属性都只接受真实色值，无法解析 CSS 变量；该文件是"图表 / 图元配色前端令牌"
> 的唯一落点（`CHART_SERIES`、`DECISION`、`GRAPH_NODE_COLOR`、`MODEL`、`PARALLEL`、`BENCH` 等），
> 与 `tokens.css` 一一对应。`.vue` 与 `.css` 中仍**零 hex**。
>
> 反之，凡是能用 DOM 绘制的图元（`HBarList` 横条、`ShapBars` 发散条、分位轴、进度条）
> 一律走 `.tone-*` 类取色，组件内不出现具体色值。

### 6. 兼容性

- 构建目标降级：`es2015` / chrome80（见 `vite.config.ts` 的 `build.target` 与 `cssTarget`）
- **不使用** `:has()` 与容器查询（`@container`）
- **仅系统字体栈**，不加载任何 Web 字体，保证内网离线可用、渲染一致
- 数字统一 `tabular-nums` 等宽对齐（`.num`）
- ECharts 按需注册，仅引入实际用到的图表与组件

## 一、A 类:必须通过

## 二、B 类:影响观感

### B1 视觉一致性

- [ ] 四个决策分析页**形态明显不同**,不是同一个模子
- [ ] 智能模型四页形态区分开(风险评分/虚开团伙/异常申报/行业基准)
- [ ] 智能应用四页中只有"自然语言取数"和"政策智能问答"是聊天形态,另两页不是
- [ ] 所有页面用同一套卡片样式、圆角、阴影、间距
- [ ] 图表配色统一走 tokens 里的图表色序
- [ ] 风险等级色标全站一致(高/中/低)
- [ ] 状态徽章样式统一(待派发/处置中/已办结/已退回)

### B2 四态处理

每个数据区都要有这四种状态,且**全站统一实现**(在 client 层处理,不是每页各写一套):

- [ ] 加载态:骨架屏或 loading,不是空白
- [ ] 空态:有说明文字和引导操作,不是空白
- [ ] 错误态:有提示和重试按钮
- [ ] 无权限态:有明确说明

> 验证方法:把 mock 的延迟改到 3000ms 看加载态;把某个 mock json 清空看空态;
> 切到 http 模式看错误态。

### B3 交互完整性

- [ ] 表格可排序的列有排序图标,点击生效
- [ ] 表格行 hover 有反馈,可点击的行光标是 pointer
- [ ] 分页器可用,切页数据变化
- [ ] 筛选条件生效,重置按钮可用
- [ ] 图表有 tooltip,hover 显示明细
- [ ] 弹窗/抽屉可关闭,ESC 键生效
- [ ] 表单必填校验生效(尤其结果回填的"误报原因"在选"无问题"时必填)

### B4 跨页跳转

凡是出现纳税人名称的地方都应可跳转到档案:

- [ ] 风险线索池的纳税人列
- [ ] 核查处置工作台的纳税人卡片
- [ ] 关联图谱的节点详情
- [ ] 重点税源监控的表格行
- [ ] 智能模型各页的结果列表
- [ ] 新办企业评估的列表

### B5 兼容性

- [ ] 在 1366×768 分辨率下无横向滚动条(政务机关笔记本常见分辨率)
- [ ] 在 1920×1080 下布局不过度拉伸
- [ ] 无 `:has()`、容器查询等新式 CSS
- [ ] 字体只用系统字体栈,无 Web 字体加载
- [ ] 如有条件,在麒麟系统的国产浏览器上实测一遍
